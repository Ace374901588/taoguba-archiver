# 淘股吧文章归档器 GUI 设计说明

本设计以 `ui-ux-pro-max` 生成的设计系统为基础，主窗口细则以页面覆盖文件为准：

- [全局设计系统](design-system/taoguba-article-archiver/MASTER.md)
- [主窗口覆盖规范](design-system/taoguba-article-archiver/pages/main-window.md)
- [可点击原型](prototype/main-window.html)

## 核心任务

用户粘贴一篇或几篇淘股吧 URL，确认登录状态、保存位置和输出格式，然后启动归档。程序默认只保存主帖正文和正文图片，不拉取评论。HTML 与 Markdown 是可叠加选项：同时勾选时，每篇文章生成一份 HTML 和一份 Markdown。

## 信息架构

```text
主窗口
├── 顶部：应用身份、登录状态、设置
├── 左侧：URL 输入、校验反馈、任务队列
├── 右侧：登录、保存位置、内容范围、输出格式
└── 底部：全局状态、开始归档 / 停止
```

单一任务不使用侧边栏或多页面导航。设置采用次级窗口，登录采用浏览器外部流程。

## 关键状态

| 状态 | 主按钮 | 页面反馈 |
|---|---|---|
| 空闲且无 URL | 禁用“开始归档” | 输入区显示格式说明 |
| URL 有误 | 禁用 | 对应行下显示原因和修正建议 |
| 未登录 | 可点击但先触发登录 | 登录卡显示明确恢复动作 |
| HTML + Markdown | 正常可用 | 提示每篇文章将生成两个文件 |
| 执行中 | “正在归档 n / total”并禁用 | 队列逐行更新；显示“停止” |
| 完成 | 恢复“开始归档” | 全局成功提示，可打开保存目录 |
| 部分失败 | 恢复，可重试失败项 | 失败行显示原因和恢复动作 |
| 登录失效 | 暂停任务 | 保留输入和进度，重新登录后继续 |

## PySide6 组件映射

| 设计组件 | PySide6 建议 |
|---|---|
| 主窗口 | `QMainWindow` + 原生标题栏 |
| URL 输入 | `QPlainTextEdit` |
| 卡片 | `QFrame` + `QVBoxLayout` |
| 登录状态 | `QLabel` / 自定义状态胶囊 |
| 保存路径 | 只读 `QLineEdit` + `QFileDialog` |
| 任务队列 | `QListView` + 自定义 Delegate |
| 进度 | `QProgressBar` |
| 全局提示 | 状态栏 + 非阻塞 Toast |
| 设置 | 独立 `QDialog` |

## 交互原则

- Playwright 运行在工作线程；GUI 永不冻结。
- 登录窗口由用户主动触发，不自动弹出。
- 用户输入在任务期间只读保留，失败后不清空。
- 默认选项应完成 90% 的使用场景；楼主跟帖放入高级选项。
- HTML 与 Markdown 使用复选框，可同时开启；不能使用互斥单选按钮。
- 所有错误都提供下一步，而不只显示错误码。

## 验收尺寸

- Windows：100%、125%、150% 缩放。
- macOS：Retina 和非 Retina 外接屏。
- 默认窗口 `1040 × 720`，最小窗口 `860 × 620`。
- 长路径、长 URL 和系统字体放大到 125% 时不得遮挡主操作。
